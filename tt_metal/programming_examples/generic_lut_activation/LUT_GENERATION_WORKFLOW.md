# LUT Generation Workflow

**Complete guide to generating all LUTs (uniform and adaptive)**

---

## Overview

The LUT generation system supports:
- **29 activations** (all PyTorch activations except GLU variants)
- **6 polynomial types** (constant, linear, quadratic, cubic, hexic, octic)
- **4 depths** (4, 8, 16, 32 segments)
- **2 modes** (uniform and adaptive segmentation)

Total possible LUTs: 29 × 6 × 4 × 2 = **1,392 LUTs** (696 uniform + 696 adaptive)

---

## Required Input Files

### 1. Configuration Files (Required)

#### `activations_config.csv`
Defines activation functions and their input ranges.

**Format:**
```csv
activation,input_range_min,input_range_max
sigmoid,-5.0,5.0
relu,-10.0,10.0
...
```

**Location:** `tt_metal/programming_examples/generic_lut_activation/activations_config.csv`

**Contains:** 29 activation definitions with their approximation domains

#### `ground_truth.py`
Python implementation of all activation functions for ground truth evaluation.

**Location:** `tt_metal/programming_examples/generic_lut_activation/ground_truth.py`

**Contains:**
- `ACTIVATION_FUNCTIONS` dict mapping names to NumPy implementations
- `get_activation_domain(name)` function returning (min, max) ranges

### 2. Adaptive Segment Files (Required for Adaptive LUTs)

#### `adaptive_segments/depth_{4,8,16,32}_segments.csv`

Pre-computed adaptive breakpoints based on curvature analysis.

**Format:**
```csv
activation,num_segments,breakpoints
sigmoid,4,-5.0,-1.2,0.0,1.2,5.0
exp,4,-5.0,-2.1,0.3,2.4,5.0
...
```

**Location:** `tt_metal/programming_examples/generic_lut_activation/adaptive_segments/`

**Files:**
- `depth_4_segments.csv` - 29 activations × 5 breakpoints (4+1)
- `depth_8_segments.csv` - 29 activations × 9 breakpoints (8+1)
- `depth_16_segments.csv` - 29 activations × 17 breakpoints (16+1)
- `depth_32_segments.csv` - 29 activations × 33 breakpoints (32+1)

**Generated by:** `generate_adaptive_segments.py` (only needs to be run once)

## Generation Scripts

### Main Script

#### `generate_luts.sh`
**Purpose:** Master script that generates all LUTs in parallel

**Usage:**
```bash
# Generate all UNIFORM LUTs (default)
./generate_luts.sh

# Generate all ADAPTIVE LUTs
./generate_luts.sh --adaptive
```

**What it does:**
1. Launches 29 parallel processes (one per activation)
2. Each process runs 6 polynomial generators:
   - `generate_piecewise_constant_luts.py` (depth-specific, no adaptive)
   - `generate_piecewise_linear_luts.py`
   - `generate_piecewise_quadratic_remez_luts.py`
   - `generate_piecewise_cubic_remez_luts.py`
   - `generate_piecewise_hexic_remez_luts.py`
   - `generate_piecewise_octic_remez_luts.py`
3. Logs output to `luts/generation_{activation}.log`
4. Waits for all processes to complete
5. Reports statistics

**Output:**
- **Uniform mode**: ~696 `.lut` files (29 activations × 24 configs)
  - 4 constant (depth-specific, one per depth)
  - 4 linear (one per depth)
  - 4 quadratic
  - 4 cubic
  - 4 hexic
  - 4 octic

- **Adaptive mode**: ~580 `_adaptive.lut` files (29 activations × 20 configs)
  - 0 constant (not supported)
  - 4 linear_adaptive
  - 4 quadratic_adaptive
  - 4 cubic_adaptive
  - 4 hexic_adaptive
  - 4 octic_adaptive

**Duration:** ~2 minutes (parallel execution)

### Individual Polynomial Generators

All generators follow the same pattern:

```bash
# Single activation, uniform segmentation
python3 generate_piecewise_linear_luts.py --activation exp

# Single activation, adaptive segmentation
python3 generate_piecewise_linear_luts.py --activation exp --adaptive

# All activations (default)
python3 generate_piecewise_linear_luts.py
```

#### 1. `generate_piecewise_constant_luts.py`
- **Polynomial degree:** 0 (constant per segment)
- **Adaptive support:** ❌ No (uniform only)
- **Depths:** 4, 8, 16, 32
- **Output format:** `{activation}_{depth}.lut`

#### 2. `generate_piecewise_linear_luts.py`
- **Polynomial degree:** 1 (slope + offset)
- **Adaptive support:** ✅ Yes
- **Depths:** 4, 8, 16, 32
- **Output format:**
  - Uniform: `piecewise_linear_{activation}_{depth}.lut`
  - Adaptive: `piecewise_linear_{activation}_{depth}_adaptive.lut`

#### 3. `generate_piecewise_quadratic_remez_luts.py`
- **Polynomial degree:** 2 (a·x² + b·x + c)
- **Method:** Remez (minimax)
- **Adaptive support:** ✅ Yes
- **Depths:** 4, 8, 16, 32

#### 4. `generate_piecewise_cubic_remez_luts.py`
- **Polynomial degree:** 3 (a·x³ + b·x² + c·x + d)
- **Method:** Remez (minimax)
- **Adaptive support:** ✅ Yes
- **Depths:** 4, 8, 16, 32

#### 5. `generate_piecewise_hexic_remez_luts.py`
- **Polynomial degree:** 6
- **Method:** Remez (minimax)
- **Adaptive support:** ✅ Yes
- **Depths:** 4, 8, 16, 32

#### 6. `generate_piecewise_octic_remez_luts.py`
- **Polynomial degree:** 8
- **Method:** Remez (minimax)
- **Adaptive support:** ✅ Yes
- **Depths:** 4, 8, 16, 32

## Complete Workflow

If `adaptive_segments/*.csv` files don't exist, generate them:

```bash
python3 generate_adaptive_segments.py
```

- `adaptive_segments/depth_8_segments.csv`
- `adaptive_segments/depth_16_segments.csv`
- `adaptive_segments/depth_32_segments.csv`

**Note:** These files are already committed to the repo, so you typically don't need to regenerate them.

### Step 1: Generate All Uniform LUTs

```bash
./generate_luts.sh
```

**Duration:** ~2 minutes
**Output:** `luts/*.lut` (696 files)

**What gets generated:**
- All 29 activations
- All 6 polynomial types
- All 4 depths
- Uniform segmentation only

### Step 2: Generate All Adaptive LUTs

```bash
./generate_luts.sh --adaptive
```

**Duration:** ~2 minutes

**What gets generated:**
- All 29 activations
- 5 polynomial types (constant excluded)
- All 4 depths
- Adaptive segmentation (uses `adaptive_segments/*.csv`)

### Step 3: Verify Generation

```bash
# Count LUTs
ls luts/*.lut | wc -l          # Should show ~1276 (696 uniform + 580 adaptive)

# Check specific activation

# View generation logs
cat luts/generation_exp.log    # Check for errors
```

## LUT File Naming Convention

### Uniform LUTs

**Constant:**
```
{activation}_{depth}.lut
Examples: sigmoid_16.lut, relu_32.lut
```

**Polynomial (linear through octic):**
```
piecewise_{type}_{activation}_{depth}.lut
Examples:
  piecewise_linear_sigmoid_16.lut
  piecewise_cubic_remez_exp_8.lut
  piecewise_hexic_remez_gelu_32.lut
```

### Adaptive LUTs

**Polynomial only (no constant):**
```
piecewise_{type}_{activation}_{depth}_adaptive.lut
Examples:
  piecewise_linear_sigmoid_16_adaptive.lut
  piecewise_cubic_remez_exp_8_adaptive.lut
  piecewise_octic_remez_tanh_32_adaptive.lut
```

## LUT Binary Format

### Uniform LUTs (Old Format - No Boundaries)

**Format:**
```
[uint32 num_values]
[float32 coefficients[num_values]]
```

**Example - Linear depth=16:**
```
num_values = 32 (16 segments × 2 coeffs per segment)
coefficients = [slope0, offset0, slope1, offset1, ..., slope15, offset15]
```

**Lookup:** Use arithmetic to compute segment index
```cpp
segment_idx = (x - x_min) / segment_width
```

### Adaptive LUTs (New Format - With Boundaries)

**Format:**
```
[uint32 num_values]
[float32 boundaries[num_segments + 1]]
[float32 coefficients[num_segments × coeffs_per_segment]]
```

**Example - Linear depth=16:**
```
num_values = 17 + 32 = 49
  - 17 boundaries (16 segments + 1)
  - 32 coefficients (16 segments × 2 coeffs per segment)

boundaries = [x0, x1, x2, ..., x16]  // 17 values
coefficients = [slope0, offset0, slope1, offset1, ..., slope15, offset15]  // 32 values
```

**Lookup:** Use binary search to find segment
```cpp
segment_idx = binary_search(boundaries, x, num_segments)
```

**Coefficients per segment:**
- Linear: 2 (slope, offset)
- Quadratic: 3 (a, b, c)
- Cubic: 4 (a, b, c, d)
- Hexic: 7 (a6, a5, a4, a3, a2, a1, a0)
- Octic: 9 (a8, a7, a6, a5, a4, a3, a2, a1, a0)

## Troubleshooting

### "No adaptive breakpoints found"

**Problem:** Adaptive generation fails with "No adaptive breakpoints found"

**Solution:**
```bash
# Check if CSV files exist
ls adaptive_segments/*.csv

# If missing, generate them
python3 generate_adaptive_segments.py

# Verify CSV has your activation
grep "exp" adaptive_segments/depth_16_segments.csv
```

### "Remez algorithm failed to converge"

**Problem:** Remez algorithm fails for certain function/depth combinations

**Solution:** This is usually fine - the script continues with other depths. The generator uses `|| true` to prevent failures from stopping the entire process.

### "Wrong number of values in LUT"

**Problem:** LUT file size doesn't match expected format

**Solution:** Regenerate the specific LUT:
```bash
python3 generate_piecewise_linear_luts.py --activation exp --adaptive
```

### Parallel generation hangs

**Problem:** `generate_luts.sh` seems stuck

**Solution:**
```bash
# Check running processes
ps aux | grep generate_piecewise

# Check log files for errors
tail -f luts/generation_exp.log

# Kill and restart
pkill -f generate_piecewise
./generate_luts.sh
```

## Quick Reference

### Generate everything from scratch:

```bash
# 1. Generate adaptive breakpoints (if not already done)
python3 generate_adaptive_segments.py

# 2. Generate all uniform LUTs
./generate_luts.sh

# 3. Generate all adaptive LUTs
./generate_luts.sh --adaptive

# 4. Verify
ls luts/*.lut | wc -l  # Should show ~1276
```

### Generate single activation:

```bash
# Uniform only
python3 generate_piecewise_linear_luts.py --activation exp

# Adaptive only
python3 generate_piecewise_linear_luts.py --activation exp --adaptive

# Both (run twice)
python3 generate_piecewise_linear_luts.py --activation exp
python3 generate_piecewise_linear_luts.py --activation exp --adaptive
```

### Check what's generated:

```bash
# Count by type
ls luts/*.lut | grep -v adaptive | wc -l           # Uniform count
ls luts/*_adaptive.lut | wc -l                     # Adaptive count

# List specific activation
ls luts/*sigmoid*

# Check for missing LUTs
./generate_luts.sh | grep "✗"  # Look for failures
```
