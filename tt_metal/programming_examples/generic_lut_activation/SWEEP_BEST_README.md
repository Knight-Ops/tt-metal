# sweep_best.sh - Run Best Configurations Only

## Overview

`sweep_best.sh` is an optimized sweep script that runs **only the best configuration** for each activation function, as defined in `$LUT_DIR/best.csv`. This is much faster than running full sweeps across all depths, degrees, and segmentation modes.

## Quick Start

1. **Create best.csv**:
   ```bash
   # Copy the example template
   cp luts/best.csv.example $LUT_DIR/best.csv

   # Edit to specify your best configs
   vim $LUT_DIR/best.csv
   ```

2. **Run the sweep**:
   ```bash
   # Run best configs for all activations
   ./sweep_best.sh

   # Run best config for specific activation
   ./sweep_best.sh --activation sigmoid
   ```

## best.csv Format

The `best.csv` file should be located at `$LUT_DIR/best.csv` (default: `/localdev/nkapre/tt-polynomial-fitter/data/luts/best.csv`).

This file is generated by the polynomial fitter's analysis tool and contains optimal configurations based on error minimization.

### CSV Structure

```csv
activation,precision,best_max_error_segments,best_max_error_degree,max_error,best_mean_error_segments,best_mean_error_degree,mean_error,num_segments,segmentation,fitting
sigmoid,bf16,32,5,3.1583e-03,32,5,2.3425e-03,32,curvature,any
gelu,bf16,16,1,3.0454e-02,32,8,5.4901e-03,16,curvature,any
tanh,bf16,32,1,5.1973e-03,32,8,2.8133e-03,32,curvature,any
```

### Column Descriptions

| Column | Description | Type |
|--------|-------------|------|
| `activation` | Activation function name | string |
| `precision` | Numeric precision (bf16 or fp32) | string |
| `best_max_error_segments` | Optimal segments for minimizing max error | int |
| `best_max_error_degree` | Optimal degree for minimizing max error | int (1,2,3,6,8) |
| `max_error` | Maximum error value achieved | float |
| `best_mean_error_segments` | Optimal segments for minimizing mean error | int |
| `best_mean_error_degree` | Optimal degree for minimizing mean error | int (1,2,3,6,8) |
| `mean_error` | Mean error value achieved | float |
| `num_segments` | Reference segment count | int |
| `segmentation` | Segmentation strategy (e.g., curvature, uniform) | string |
| `fitting` | Fitting method (e.g., any, remez) | string |

**Note**: The script skips activations with `inf` error (not approximable).

### Error Metric Selection

By default, `sweep_best.sh` uses the **mean error** configuration (`best_mean_error_segments` and `best_mean_error_degree`).

Use `--use-max-error` to optimize for max error instead.

### LUT Filename Construction

The script constructs the exact LUT filename from CSV values:
```
{activation}_{precision}_{segments}_{degree}_{segmentation}_{fitting}.lut
```

**Example**:
- CSV row: `sigmoid,bf16,32,5,...,32,curvature,any` (mean error config)
- LUT filename: `sigmoid_bf16_32_5_curvature_any.lut`

```bash

```

| Option | Description | Default |

## Generating best.csv

The `best.csv` file is generated by the **polynomial fitter analysis tool** (in the `tt-polynomial-fitter` repository), not manually created. The tool:

1. Analyzes LUT approximation quality across multiple configurations
2. Tests different segment counts (4, 8, 16, 32)
3. Tests different polynomial degrees (1, 2, 3, 6, 8)
4. Identifies optimal configuration per activation for:
   - Minimizing max error
   - Minimizing mean error

### Regenerating best.csv

If you've added new LUTs or activations, regenerate best.csv:

```bash
cd $LUT_DIR
python analyze_best_configs.py --output best.csv
```

The analysis tool will:
- Scan all LUT files in the directory
- Evaluate approximation quality
- Output best configurations per activation

### Manual Override (Advanced)

If you need to manually override specific entries:

```bash
# Backup current best.csv
cp $LUT_DIR/best.csv $LUT_DIR/best.csv.bak

# Edit specific activations
vim $LUT_DIR/best.csv
```

**Format**:
```csv
activation,precision,best_max_error_segments,best_max_error_degree,max_error,best_mean_error_segments,best_mean_error_degree,mean_error,num_segments,segmentation,fitting
sigmoid,bf16,32,5,3.1583e-03,32,5,2.3425e-03,32,curvature,any
```

**Important**: Ensure error values are accurate - they're used for validation.

## Integration with Full Sweeps

### Typical Workflow

1. **Initial exploration** - Run full sweeps to explore all configurations:
   ```bash
   ./sweep_piecewise.sh --degree cubic
   ```

2. **Analysis** - Analyze results and determine best configs

3. **Create best.csv** - Populate best.csv with optimal configurations

4. **Validation** - Run sweep_best.sh for quick validation:
   ```bash
   ./sweep_best.sh
   ```

5. **Regular testing** - Use sweep_best.sh for routine regression testing

### Benefits of sweep_best.sh

- **Speed**: ~30x faster than full sweep (30 configs vs 900+ configs)
- **Focused**: Tests only production-quality configurations
- **Reproducible**: Consistent baseline for performance tracking
- **CI-friendly**: Fast enough for continuous integration

## Troubleshooting

### Error: Best configuration file not found

```bash
❌ ERROR: Best configuration file not found: /localdev/nkapre/tt-polynomial-fitter/best.csv
```

**Solution**: Create best.csv from the example template:
```bash
cp luts/best.csv.example $LUT_DIR/best.csv
vim $LUT_DIR/best.csv
```

### Error: LUT file not found

```
SKIP (LUT not found)
```

**Causes**:
1. LUT file doesn't exist at `$LUT_DIR`
2. Filename doesn't match the expected pattern
3. Wrong precision/segmentation/fitting specified

**Solution**:
```bash
# Check if LUT exists
ls $LUT_DIR/sigmoid_bf16_32_3_curvature_any.lut

# Generate missing LUTs
cd /path/to/tt-polynomial-fitter
python generate_luts.py --activation sigmoid --depth 32 --degree 3
```

### Error: Binary not found

```
SKIP (binary not found: .../programming_examples_generic_lut_activation_pc_32)
```

**Solution**: Build the required binaries:
```bash
cd $REPO_ROOT
./build_metal.sh --build-programming-examples
```
