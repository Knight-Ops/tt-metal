### 2. Kernel Implementation Analysis
- **Question**: Are cubic and quadratic kernels the same?
- **Answer**: No, structurally similar but different:
  - **Quadratic**: 3 coefficients (a, b, c), evaluates `y = (a*x + b)*x + c`
  - **Cubic**: 4 coefficients (a, b, c, d), evaluates `y = ((a*x + b)*x + c)*x + d`
  - **Key difference**: Cubic computes result inside v_if blocks, quadratic loads coefficients first

**Files analyzed:**
- `kernels/compute/piecewise_quadratic.cpp`
- `kernels/compute/piecewise_cubic.cpp`

## Quick Sweep Analysis Results (Blackhole)

### Executive Summary
- **Winner**: Cubic Remez (Depth 32, Tile 64) - MAE: 0.001082, Runtime: 72.1ms
- **Best Balance**: Quadratic Remez (Depth 32, Tile 64) - MAE: 0.000591, Runtime: 70.8ms (2× better accuracy than Native SFPU)
- **Fastest**: Native SFPU - Runtime: 54.8ms (29% faster but less accurate)

### Key Findings

#### 1. Runtime Variance Patterns (Surprising Discovery)
- **Native SFPU**: Stable at both 32 and 64 tiles (1.3-1.4% CV)
- **Constant**: Stable at 32 tiles (1.9% CV), **unstable at 64 tiles (71.8% CV)** ⚠️
- **Linear**: **Unstable at 32 tiles (84.0% CV)**, stable at 64 tiles (1.5% CV) ⚠️
- **Quadratic/Cubic**: Stable at both tile sizes (~1.2-1.4% CV)

**Hypothesis**: Constant/Linear have tile-size-dependent kernel launch overhead issues

#### 2. Activation-Specific Winners
- **gelu**: Cubic wins by 10.2× (MAE: 0.00010 vs 0.00102 for Native)
- **sigmoid/swish/mish/softsign**: Native SFPU not available, LUT required
- **tanh/erf**: Native SFPU wins (lower overhead for simple functions)
- **softplus**: Quadratic wins by 1.6× over Native SFPU

#### 3. Depth Analysis
- **Constant**: 3.1× improvement from depth 8 to 32
- **Linear**: 9.4× improvement from depth 8 to 32
- **Quadratic**: 6.4× improvement from depth 8 to 32
- **Cubic**: Only 1.2× improvement (diminishing returns, already accurate at depth 8)

### Production Recommendations
1. **Primary choice**: Quadratic Remez (depth 32) - best accuracy/runtime balance
2. **When native available**: Use Native SFPU for tanh, erf, relu, leaky_relu
3. **For accuracy-critical**: Cubic Remez (depth 32) for gelu, sigmoid, softplus
4. **Avoid**: Constant/Linear for exp (catastrophic errors), 64 tiles for Constant, 32 tiles for Linear

## Technical Decisions Made

### 1. Git Strategy for Concurrent Sweeps
- **Initial plan**: Pull/rebase before each push to merge results from both servers
- **Final decision**: No git operations in detached sessions
  - **Reason**: SSH keys not available after disconnection
  - **Alternative**: Collect results manually via scp after completion

### 2. Session Management: Tmux vs Screen vs Nohup
- **Chosen**: Tmux
  - **Pros**: Can reattach to live session, better logging, universally available
  - **Cons**: Requires installation (added to setup_server.sh)
  - **Why not screen**: Not available on servers by default
  - **Why not nohup**: Cannot reattach or monitor interactively

### 3. CSV Naming Strategy
- **Chosen**: Platform prefixes (`blackhole_*.csv`, `wormhole_*.csv`)
- **Alternative considered**: Subdirectories (rejected - more complex for plotting scripts)
- **Benefit**: Enables parallel collection and comparison of results

### 4. Python Environment
- **Issue**: `python_env` virtual environment doesn't exist on servers
- **Solution**: Use system python3 directly
- **Justification**: Required packages (numpy, mpmath) already installed system-wide
