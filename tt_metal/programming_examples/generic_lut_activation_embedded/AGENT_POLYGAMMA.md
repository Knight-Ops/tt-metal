# Polygamma SFPU Uplift Plan

## Goal
Replace the composite `_polygamma` implementation with a first-class unary SFPU kernel using LUT-based polynomial approximation, following the same pattern as digamma and lgamma.

## Current State
- **Composite implementation**: `_polygamma(input, k, ...)` in `unary_composite_op.cpp`
  - Decomposes into: `(-1)^(k+1) * factorial(k) * zeta(k+1, x)` using digamma + series
  - Takes `int32_t k` parameter (order: k=1 is trigamma, k=2 is tetragamma, etc.)
- **No SFPU kernel**: `UnaryOpType` has no `POLYGAMMA` entry
- **Binding**: `bind_unary_composite_int<"polygamma", &ttnn::polygamma>` in `unary_nanobind.cpp`
- **Coefficients**: `best.csv` has `polygamma p1_s2` (degree 1, 2 segments) — very simple fit
- **Domain**: [0.01, 10.0] from `activations/polygamma.json`

## Key Difference from Digamma/Lgamma
Polygamma takes an **integer parameter `k`** (the order). The LUT coefficients are fit for a specific `k` value. We need to decide:

1. **Single k**: Fit for k=1 (trigamma, most common) only. Other k values fall back to composite.
2. **Multiple k**: Generate separate LUTs for k=1,2,3,... and dispatch based on the parameter.

**Recommendation**: Start with k=1 (trigamma) only. The `best.csv` coefficients are for trigamma. Add a runtime check: if k==1, use SFPU; else, fall back to composite.

## Notes
- The `k` parameter dispatch is the tricky part. Check how `softplus` handles `beta`/`threshold` params — it uses `SFPU_UNARY_THREE_PARAM_KERNEL_FN`. Polygamma needs `SFPU_UNARY_ONE_PARAM_KERNEL_FN` for `k`.
- If `k != 1`, the SFPU kernel should return the input unchanged or NaN, and the Python layer falls back to composite. OR: just support k=1 only and document it.
- The `polygamma_bw` backward op also uses `_polygamma` — needs updating to call the new unary path.
- `best.csv` shows p1_s2 (degree 1, 2 segments) — very simple. May need refitting for better accuracy.
